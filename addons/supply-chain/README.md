# addon : supply-chain

Dependency security and SBOM (Software Bill of Materials) generation.

## When to add

Your project :
- Publishes to PyPI / npm / Docker Hub
- Is used in production / regulated environments
- Has > 10 direct dependencies
- Wants to detect supply-chain attacks early

Pre-2026, SBOM was "enterprise only". Post-XZ-backdoor (2024), it's
becoming standard for any project shipping binaries or to package
registries.

## What it adds

| File | Purpose |
|---|---|
| `.github/workflows/sbom.yml` | Generate CycloneDX SBOM on every release |
| `.github/dependabot.yml` | Automated dependency PRs (security + version) |
| `.github/workflows/scorecard.yml` | OpenSSF Scorecard for repo hygiene |
| `requirements.lock` (template) | Pinned exact dependency versions for reproducibility |

## Why this works

- **SBOM (CycloneDX)** is now a SOC 2 / ISO 27001 compliance expectation.
  Tooling : `cyclonedx-py` for Python, `cyclonedx-npm` for Node.
- **Dependabot** opens automated PRs for security patches. Configure
  conservatively (security-only) for solo dev ; aggressively (weekly
  minor bumps) for active teams.
- **OpenSSF Scorecard** gives a public score (out of 10) for repo
  hygiene. Useful signal for users evaluating your project.

## Integration with core template

- Workflows go in `.github/workflows/`
- `dependabot.yml` in `.github/`
- `requirements.lock` at root (generated by `pip-compile` or `pip freeze`)
- Trigger SBOM workflow on release tags (`v*`)

## Cost

- SBOM workflow : runs on every release, ~30 seconds CI
- Dependabot : you'll get 2-5 PRs per month to review
- OpenSSF Scorecard : weekly run, public score

Worth it once your project is publicly available and people depend on it.
